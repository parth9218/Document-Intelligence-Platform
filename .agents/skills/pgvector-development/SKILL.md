# Skill: pgvector Vector Operations

## Purpose
Configure vector dimensions, indexes, and database similarity logic.

## Best Practices
* Titan Embeddings V2 requires defining a 1024-dimension float array column in PostgreSQL.
* Apply HNSW indexes for high efficiency. Do not run cosine distance operations without matching index targets.
* Formulate parameter bindings carefully. Ensure the user-supplied string binds correctly before casting: `embedding <=> $1::vector`.

## Common Mistakes
* Attempting to compare query vectors against document vectors generated by different models.
* Leaving HNSW parameters default on databases containing large vector dimensions.

## Validation Checklist
- [ ] Column size set to exactly 1024 dimensions?
- [ ] Cosine distance operator (`<=>`) matches target HNSW vector indexes?
- [ ] SQL bindings avoid string templates?
