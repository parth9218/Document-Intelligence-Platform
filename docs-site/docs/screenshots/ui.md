# Application UI Showcase

> Visual walkthrough of the Next.js frontend client — covering document onboarding, direct S3 multipart batch uploads, real-time Server-Sent Events (SSE) ingestion tracking, and grounded Q&A with verifiable citations.

The frontend is a statically-exported Next.js SPA served from Amazon S3 via Amazon CloudFront. All API traffic (`/api/*`) is reverse-proxied through CloudFront to the internal Kubernetes Application Load Balancer (ALB).

---

## Intelligence Workspace — Empty Onboarding State

The initial view presented on first session load. The session token (truncated in the header) is cryptographically generated by the API, signed with HMAC-SHA256, and stored in an `HttpOnly` cookie. The **Session Limits** panel reflects live quota state queried from the database.

## Batch Upload in Progress — Direct S3 Transfer

Four documents being processed simultaneously. The `Processing Queue & Documents (4)` header tracks the live document count. Individual cards show:

- **`UPLOADING`** — XHR `XMLHttpRequest` direct multipart POST to S3 via presigned POST credentials. Progress bar reflects actual XHR `upload.onprogress` events, **not** polled from the server.
- **`UPLOADED`** → transitioning to `EMBEDDING` — the S3 `ObjectCreated` event has notified SQS; the Python worker has picked up the message and is beginning vector embedding.
- **`PENDING UPLOAD`** — document is queued client-side; waiting for an upload slot (limit: 5 concurrent).
- **Session Limits** panel: `4 / 5 slots` active, `5.78 MB / 50.00 MB` storage consumed.

## Worker Pipeline — Active Embedding with SSE Progress

Documents mid-ingestion. The `EMBEDDING (92% complete)...` progress label and cyan progress bar are driven by **real-time Server-Sent Events (SSE)**. The flow: Python worker commits a batch checkpoint to PostgreSQL → a `pg_notify` trigger fires on `progress_{sessionId}` channel → the Express API's `LISTEN` subscriber forwards the event → the browser's `EventSource` updates the document card — all without polling.

## Grounded Q&A — Empty Chat State (No Documents Processed)

The `Ask Assistant` tab with no processed documents. The amber warning banner enforces the application invariant: **the chat input is disabled until at least one document reaches `completed` status.** This prevents meaningless queries against an empty vector index.
