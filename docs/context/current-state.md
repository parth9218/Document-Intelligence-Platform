## Current Code State

- **API Service (`/apps/api`)**: Refactored into a production-grade modular architecture. Enforces separation of concerns via Routes, Controllers, Services, and structural Validators. Configured with a central environment-aware configuration module (`config/`), custom HTTP/business error classes (`errors/`), centralized Express error handler middleware, and a structured logger (`utils/logger.ts`) producing JSON in non-local environments and colorized text locally (`NODE_ENV === 'local'`). File validation supports central configurations and easily extensible MIME types following the Open/Closed Principle. DB interactions leverage pgPool connection pooling (SSE streams) and Prisma transactions (batch upload metadata initializations & confirm-upload status updates). Upload confirmation (`POST /api/documents/:id/confirm-upload`) is fully idempotent, returning `200 OK` and ignoring the update if the SQS worker has already transitioned the document into a processing or completed state, while returning `409 Conflict` for invalid states (`expired`, `cancelled`). Scheduled cleanup daemon handles expired and stuck uploads. **SSE and status endpoints are fully refactored to session-scoped equivalents (`GET /api/documents/progress`, `GET /api/documents/status`) per ADR-017, using session-scoped PG NOTIFY channels.** **CORS middleware (ADR-018) is globally registered in `app.ts` using the `cors` package with environment-driven origin policy: dynamic reflection locally, strict `CORS_ALLOWED_ORIGIN` whitelist in non-local environments. Wildcard `*` is never returned when credentials are enabled. Preflight OPTIONS requests are handled with a 24-hour `Max-Age` cache.** **RDS IAM Database Authentication is supported via `@aws-sdk/rds-signer` token utility (`src/utils/rds-auth.ts`) with a 10-minute in-memory token cache. `db.ts` configures `pgPool` with dynamic password resolution when `DB_IAM_AUTH_ENABLED=true` and integrates Prisma Client via `@prisma/adapter-pg` driver adapter (`PrismaPg`).**

Graceful shutdown is handled on SIGINT/SIGTERM, and a secondary thread handles DLQ message transitions. ## Operational Warnings

- Ensure local Docker runs pgvector before implementing Task 101.
- Verify local environment variables avoid colliding with AWS profile parameters.
- The PG NOTIFY trigger on `processing_jobs` must be appended to the Prisma-generated migration SQL — it cannot be expressed in `schema.prisma` directly.
- `EMBEDDING_PROVIDER=local` env var switches worker embedding from Bedrock to Sentence-Transformers. Must be set in local `.env` during development.
- SQLAlchemy models in `apps/worker/models.py` must be manually kept in sync with Prisma schema changes. Prisma Migrate is the single source of truth.
- SQS visibility timeout is 600 seconds (10 min). Adjust if processing times exceed this during testing.
- Ensure any background Python worker daemon processes are terminated before executing integration tests to avoid SQS message theft.
- `S3_BUCKET_NAME` must be set in `/apps/worker/.env` (configured as `documents-bucket` locally).
