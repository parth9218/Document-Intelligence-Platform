## Current Code State

- **API Service (`/apps/api`)**: Refactored into a production-grade modular architecture. Enforces separation of concerns via Routes, Controllers, Services, and structural Validators. Configured with a central environment-aware configuration module (`config/`), custom HTTP/business error classes (`errors/`), centralized Express error handler middleware, and a structured logger (`utils/logger.ts`) producing JSON in production and colorized text in development. File validation supports central configurations and easily extensible MIME types following the Open/Closed Principle. DB interactions leverage pgPool connection pooling (SSE streams) and Prisma transactions (batch upload metadata initializations & confirm-upload status updates). Upload confirmation (`POST /api/documents/:id/confirm-upload`) is fully idempotent, returning `200 OK` and ignoring the update if the SQS worker has already transitioned the document into a processing or completed state, while returning `409 Conflict` for invalid states (`expired`, `cancelled`). Scheduled cleanup daemon handles expired and stuck uploads. **SSE and status endpoints are fully refactored to session-scoped equivalents (`GET /api/documents/progress`, `GET /api/documents/status`) per ADR-017, using session-scoped PG NOTIFY channels.** **CORS middleware (ADR-018) is globally registered in `app.ts` using the `cors` package with environment-driven origin policy: dynamic reflection in development/test, strict `CORS_ALLOWED_ORIGIN` whitelist in production. Wildcard `*` is never returned when credentials are enabled. Preflight OPTIONS requests are handled with a 24-hour `Max-Age` cache.**
- **Worker Service (`/apps/worker`)**: Implemented. Follows a modular, production-grade structure containing configuration management (`app/config/settings.py` via `python-dotenv`), JSON-structured logging (`app/utils/logger.py`), dual ORM models (`app/models/document.py`, `app/models/job.py` using SQLAlchemy), repository handlers (`app/repositories/job_repository.py`), AWS SQS client (`app/clients/sqs_client.py`), AWS Bedrock client (`app/clients/bedrock_client.py`), message consumer (`app/consumers/sqs_consumer.py`), job handler (`app/handlers/job_handler.py`), document extractor (`app/services/extractor.py`), paragraph chunker (`app/services/chunker.py`), and configurable vector embeddings generator (`app/services/embeddings.py` supporting Bedrock and Local SentenceTransformers via environment parameters). Graceful shutdown is handled on SIGINT/SIGTERM, and a secondary thread handles DLQ message transitions. Includes unit/integration tests (`apps/worker/tests/test_worker.py`, `apps/worker/tests/test_chunker.py`, `apps/worker/tests/test_embeddings.py`, `apps/worker/tests/test_integration.py`).

## Operational Warnings

- Ensure local Docker runs pgvector before implementing Task 101.
- Verify local environment variables avoid colliding with AWS profile parameters.
- The PG NOTIFY trigger on `processing_jobs` must be appended to the Prisma-generated migration SQL — it cannot be expressed in `schema.prisma` directly.
- `EMBEDDING_PROVIDER=local` env var switches worker embedding from Bedrock to Sentence-Transformers. Must be set in local `.env` during development.
- SQLAlchemy models in `apps/worker/models.py` must be manually kept in sync with Prisma schema changes. Prisma Migrate is the single source of truth.
- SQS visibility timeout is 600 seconds (10 min). Adjust if processing times exceed this during testing.
- Ensure any background Python worker daemon processes are terminated before executing integration tests to avoid SQS message theft.
- `S3_BUCKET_NAME` must be set in `/apps/worker/.env` (configured as `documents-bucket` locally).
